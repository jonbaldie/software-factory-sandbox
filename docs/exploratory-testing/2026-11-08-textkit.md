## Journeys

### Fit a field with padding

A consumer wants a centered field with the requested grapheme width. `padCenter('ab', 5, '*')` returned `'*ab**'`. The decomposed input `padCenter('e\u0301', 5)` returned two spaces on each side. Emoji fills also produced the documented code-point widths in `padLeftTo` and `padRightTo`.

A valid one-code-point combining fill exposes a mismatch between two documented promises. `padCenter('a', 5, '\u0301')` returned `'\u0301\u0301a\u0301\u0301'`. `Intl.Segmenter` counted two grapheme clusters, not five. The U+200D fill variation also produced two clusters. Both cases repeated in a fresh process. A consumer relying on the stated width can see misalignment. [Issue #174](https://github.com/jonbaldie/software-factory-sandbox/issues/174) records the reproduction. Triage marked the issue `ready-for-human` and requested a fill-policy decision. [Issue #46](https://github.com/jonbaldie/software-factory-sandbox/issues/46) addressed decomposed input rather than joining fill. [Issue #146](https://github.com/jonbaldie/software-factory-sandbox/issues/146) concerns padding performance.

### Fit text into a line

A consumer wants wrapped or truncated text to respect code-point limits. `wordWrap('The quick brown fox', 10)` returned `'The quick\nbrown fox'`, and `truncate('The quick brown fox', 12)` returned `'The quick…'`. The emoji variations returned `'😀😀\n😀\nok'` for wrapping at width two and `'😀😀…'` for truncation at width three. The outputs met the documented limits in both runs.

### Add and remove literal affixes

A consumer wants to add URL and file suffixes without duplicating them, and remove one matching affix. `ensurePrefix` and `ensureSuffix` returned the expected values both before and after the affix was present. `stripPrefix('vv1', 'v')` returned `'v1'`, and `stripSuffix('report.txt.txt', '.txt')` returned `'report.txt'`. The empty-suffix variation returned `'report'`, consistent with the rejection of the earlier incorrect fixture in [issue #117](https://github.com/jonbaldie/software-factory-sandbox/issues/117).

## Classification and limits

The combining-fill discrepancy is confirmed. Issue #174 entered triage and now needs a human decision. No other candidate remains unresolved. No product fix was made. The remaining helpers, factory workflows, terminal column widths, large inputs, other Node versions, and browser consumers were outside this pass. The tests compare returned values and do not establish behavior in a rendered terminal. There were no setup or access blockers.

The API currently accepts a fill that cannot produce the promised width in the tested case. That observation is a contract ambiguity for maintainers to resolve, not a recommendation for a particular implementation.
